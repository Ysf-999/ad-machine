# Private review and decision service (prototype) — mocked only, never hosted

Not used by the ad board (`cloud/dash.py` + `cloud/frame_review.py` serve on 127.0.0.1 only).

Threats covered: stolen/replayed links, cross-ad access, modified decision bodies, stale approvals, unauthenticated browsing, CSRF on decisions, credential exposure through logs/referrers and request flooding. We assume a trusted private host/filesystem/runtime and an owner-controlled TLS origin. Host compromise, a signing-key holder, a malicious uploaded HTML dependency and provider billing are outside this layer's guarantee. No listener, bucket, TLS certificate, domain or account was created.

Use separate keys for review access, callback requests and production decisions. No key is stored in source or the auth database. HMAC access tokens bind domain/version/ad/scope/issued/expiry/nonce and expire within one hour. Constant-time signature verification precedes use; an atomic durable used-nonce record prevents replay. A one-time view link exchanges into a random scoped Secure/HttpOnly/SameSite=Strict cookie and redirects to a clean URL. Cookie sessions expire with the link and their stored hashes are keyed, so access-key rotation also invalidates sessions. View sessions cannot authorize decisions.

POST /ads/AD/decision requires a separate single-use decision access token in Authorization, exact configured HTTPS Origin, bounded body and a body workspace_id matching the scoped real ad. It then delegates the original signed JSON to the existing production Application/approval validator. The wrapper cannot sign approvals or waive frames/QC/masterqc/manual/final/all-hooks requirements. Failed/malformed/stale production decisions remain rejected, even with valid access authentication. Tests delegate to an explicit fake application; no genuine real-ad decision was created.

Rate limits are durable fixed one-minute buckets keyed by a private HMAC of the trusted socket peer. Do not trust a client-supplied X-Forwarded-For header. Audit stores time, pseudonymous peer, safe ad scope and controlled outcome only. Never log full URL query/access tokens, cookies, Authorization, request bodies, prompt text or approval notes. Error replies redact details. Responses set private/no-store, no-referrer, nosniff and a restrictive CSP. Original private plan/jobs/code/database files are refused even if mistakenly present in the declared review bundle. Asset serving still uses the original exact-file review allowlist.

The pure authenticated_application factory wires this layer around an existing real workflow; handler_for forwards request headers/trusted peer without binding a server. The old localhost-only CLI server is not a private hosted deployment and was not started or converted into public hosting. A production host must use the authenticated factory, trusted reverse proxy TLS/origin configuration, body/time/range limits, private database permissions and a tested revocation/backup/rotation policy. Multiple service instances need a shared transaction/replay/rate authority; local SQLite alone is not distributed security proof.

## Private static-bundle layout

Private bucket prefix: reviews/WORKFLOW/AD/INPUT_SHA256/. Include only declared REVIEW.html, MASTER.mp4, approved preview media and current QC/preflight reports plus a hash/size manifest. Exclude plan.json, jobs.jsonl, code, source footage, queue/auth databases and signing keys. No public ACL/listing. A small authenticated decision endpoint validates access and delegates the separate existing signed decision. Browser media access needs same-origin scoped sessions or exact private signed asset URLs; ordinary relative HTML does not propagate query tokens. Range streaming/private CDN caching and real object-store policies are untested.

Owner must choose host/private bucket, domain/TLS origin, access recipients and notification channel, provision distinct keys and decide retention/revocation. Nothing here sends, uploads or publishes. Six tests cover scopes, expiry/tampering/replay, cookie/decision separation, cross-workspace refusals, rate limits, private-plan denial and session invalidation on rotation. These tests are authentication behavior evidence, not an external penetration test or hosting readiness claim.
