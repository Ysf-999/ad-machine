# Isolation interface (prototype runner) — Mac Seatbelt real; Linux written and mocked only

`worker.isolation` separates capability probing, immutable Runtime configuration, command planning and execution. The existing runner selects the Mac implementation and retains the exact original Seatbelt prefix: no network, workspace-only writes except /dev/null, original-tree reads refused except the declared workspace and pinned venv. Existing real gate evidence was measured under that policy. The runner still refuses Linux unless the complete new execution-plan path and an approved runtime are supplied; merely finding docker/bwrap is insufficient.

Container plans specify pull=never, network=none, read-only image/root, read-only input/runtime mounts, one writable work mount, non-root host UID, no new privileges/capabilities, PID/memory/CPU bounds and an empty inherited environment. Worker variables are explicit argv environment assignments. Bubblewrap plans use an explicit minimal offline rootfs, read-only runtime/input mounts, only work writable, empty environment, all namespaces including network, parent-death handling, and outer unshare user/net namespaces. They never bind the host root or credential directories. No shell is admitted as an executable.

Runtime Python, ffmpeg, ffprobe, fonts, model cache and temporary paths are manifest fields. Model fetching and Claude/moments calls are disabled. Exact artifact hashes must be verified when the runtime manifest is materialized; paths alone prove no binary provenance. Fonts/fontconfig integration and OCR replacement remain separate gates. Existing original tools still have host assumptions: this interface does not claim their full Linux runtime closure is complete.

`probe` performs executable discovery only unless supplied a trusted capability checker. Tests inject confirmed capabilities and process execution, asserting argv/mounts/network/environment and fail-closed behavior. A real Linux host must verify namespace permissions, subordinate UID maps, rootfs libraries, ffmpeg/font resolution, model compatibility, signal/group reaping, disk/resource cgroups and every original ad gate before any Linux parity claim.
